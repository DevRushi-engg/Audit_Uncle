````
Build "Munim" from scratch: a single-page web app where a small-business owner drops in an anonymized sales CSV and a team of on-device AI agents returns a cash flow dashboard, a tax estimate, a runway projection, a what-if simulator, and a plain-language "ask your data" box. One-line pitch: "drop your sales CSV, get your hisab — your data never leaves this device."

Problem: micro-business owners (kirana stores, tiffin services, salons) have sales records but no CFO. Cloud finance tools need signups and data uploads they don't trust, and spreadsheets are intimidating.
Goal: make a private, local-first financial health checker that pairs deterministic, trustworthy math with a visible team of small open-source AI agents that explain the numbers in simple English or Hinglish.
Audience: micro-business owners and the students demoing it to them — an estimate tool, not an accounting or tax-filing product.

Core principle (very important): AI PLANS AND EXPLAINS, CODE CALCULATES. Every number shown in the UI must come from deterministic TypeScript functions. The language model may only choose which tool to run and narrate numbers that code already produced. It must never invent or compute figures.

Non-goals: no auth/accounts, no backend, no database, no API routes that receive user data, no bank/UPI/Tally/accounting integrations, no GST return filing, no invoicing, no multi-user or collaboration, no Telegram/WhatsApp bot, no automated test suite/CI.

- IDE/agent: Antigravity (you)
- Framework: Next.js 16, App Router
- UI: React 19 + TypeScript
- Styling: Tailwind CSS v4
- Charts: Recharts

- On-device AI: `@mlc-ai/web-llm` running "Qwen2.5-1.5B-Instruct-q4f16_1-MLC" in the browser (WebGPU), with an optional Ollama provider (http://localhost:11434) and a built-in deterministic "template narrator" fallback so the app NEVER dead-ends if AI is unavailable
- Hosting target: Vercel as a fully static client app (no server code needed)
- Secrets: none. There is no API key anywhere in this project.
- Privacy rule: user CSV data must never be sent over the network. The only allowed network traffic is (a) the one-time WebLLM model download from its CDN, cached afterward, and (b) an optional request to localhost Ollama. Do not add analytics, fonts-from-third-party tracking, or any telemetry.

Color tokens: paper #FBF6E9, paper-deep #F3EAD3, rule #E2D6B8, ink #1A1A1A, muted-ink #6B645A, turmeric #E8A317, ledger-red #A8231B, tulsi-green #2E7D4F, pen-blue #23408E, night-slip #1C1B18, night-ink #F4EEDD. Core user flow:
1. User lands on the app, sees the on-device privacy chip and an empty dashboard with a "Try sample" option.
2. User drops a CSV (or picks a sample: Kirana store, Tiffin service, Messy CSV). The app auto-detects columns and shows a column mapper with a 5-row preview.
3. User sets opening cash balance, business type, and narrator language (English or Hinglish). Optionally clicks "Load on-device AI (~900 MB, one time)". Without it, the template narrator is used.
4. User clicks "Analyze" (or presses Ctrl+Enter / Cmd+Enter from anywhere). Five agents run in order and are visible in the Agent Room: Cleaner, Analyst, Tax, Risk, CFO.
5. The dashboard fills in: health score stamp, KPI row, cash flow chart with forecast, runway card, tax estimate card, insights, CFO memo.
6. User can ask questions in the Ask box and drag sliders in the What-If panel; everything updates live from deterministic math.

=== 5. lib/csv/ (browser-only) ===
parse.ts: parseCsvFile(file: File): Promise<{ headers, rows }> using PapaParse (header: true, skipEmptyLines). Reject files over LIMITS.maxFileMB or rows over LIMITS.maxRows with friendly messages.
detect.ts: detectMapping(headers, sampleRows): ColumnMapping — match header names case-insensitively against synonyms (date/day/dt/txn date; amount/amt/total/value/sale; type/kind/dr-cr; category/item/head; mode/payment/pay mode) and fall back to sniffing values (date-like, numeric, cash/upi/card words). Return per-column role plus a boolean `autoDetected`.
clean.ts: cleanRows(rows, mapping): { transactions: Transaction[], report: CleanReport }. Rules: parse dates in yyyy-mm-dd, dd/mm/yyyy, dd-mm-yy, d/m/yyyy (assume day-first for ambiguous); strip ₹, "Rs", commas, spaces from amounts; if no type column, positive amounts = sale and negative = expense; type column accepts sale/sales/income/cr/credit and expense/purchase/debit/dr; map payment words to cash/upi/card/other (gpay/phonepe/paytm -> upi); drop rows missing a valid date or amount and count them; do NOT dedupe (repeat sales are legitimate) but warn if more than 5% of rows are exact duplicates; sort by date; compute dateFrom/dateTo/days; count datesFixed and amountsFixed for the Cleaner agent.

=== 6. lib/finance/ (pure functions, no React, no AI) ===
format.ts: formatINR(n) using Intl "en-IN" with ₹ and no decimals (₹1,23,456), formatDays(n), formatPct(n, 1 decimal).
metrics.ts: buildDailySeries(transactions, openingCash) filling missing days with zeros and a running balance (openingCash = cash at start of first date); computeFacts(...) returning totals, last-7/30-day averages, previous-30-day comparison deltas, weekday averages (Mon-Sun), best and worst day, payment-mode split (cash share %), top 5 expense categories, cashNow = openingCash + sales - expenses.
runway.ts: survivalDays = cashNow / average daily expenses over the last 30 days (or all days if fewer than 30); null when average expenses are 0 or when days < LIMITS.minDaysForRunway. trendDays: if average daily net over last 30 days is negative, cashNow / abs(net); otherwise "cash-positive". Always include a plain-English `assumption` string ("if sales stopped today and expenses continued at the last 30-day average").
forecast.ts: forecastNext(series, forecastDays): for each future day use that weekday's mean sales over the last 4 weeks and the last-30-day average daily expenses; build a projected balance path; low/high band = baseline +/- one standard deviation of weekly net scaled to the horizon. Pure and deterministic.
tax.ts: estimateTax(facts, businessType): annualize turnover from the data window; pick the regime from TAX config; gstPayable = collected-rate math per config (composition: rate * turnover; regular: rate * sales minus rate * eligible purchases, floored at 0); income tax via presumptive profit (digital share decides 6% vs 8%) then TAX.incomeTaxSlabs; return rulesUsed text and TAX_DISCLAIMER. Never hardcode rates in this file.
score.ts: computeScore(facts) using SCORE_WEIGHTS — runway (full marks at >= 90 days survival, zero at <= 15), margin (net/sales, full at >= 15%), trend (last 30 vs previous 30 sales), cashReliance (lower cash share = more traceable, full at <= 50%), taxReadiness (turnover within presumptive cap and digital share >= 50%). Return total, band, and the five factors each with a one-line note. Pure function, fully deterministic.
flags.ts: buildFlags(facts): rules, e.g. survival runway < 30 days -> HIGH, < 60 -> MEDIUM; expense ratio > 85% -> MEDIUM; one weekday > 35% below average -> LOW with the weekday name; cash share > 80% -> LOW (hard to evidence receipts); single day > 25% of total sales -> LOW.
whatif.ts: runWhatIf(facts, input): apply priceChangePct to forecast sales with volume change = -priceChangePct * ASSUMPTIONS.priceElasticity; apply expenseChangePct to expenses; subtract oneTimeSpend from cash on day 1; return baseline vs scenario for runwayDays, net30 and endCash plus deltas.
tools.ts: the ONLY functions the Ask feature may call, each returning { tool, args, numbers: Record<string, string>, rows?: string[][] }: totalSales(period: "7d"|"30d"|"all"), bestWorstDays(), weekdayPerformance(weekday?), affordability(amount) (compares amount with cashNow, projected 30-day end balance low band, and runway after spending), runwayNow(), topExpenses(). All numbers pre-formatted by format.ts.

=== 8. lib/ai/ (browser-only, never imported by scripts) ===
provider.ts: interface NarratorProvider { id, label, isReady(): boolean, load?(onProgress: (pct: number, text: string) => void): Promise<void>, generate(opts: { system: string, user: string, maxTokens: number, json?: boolean }): Promise<string> }. Export getProvider(id) and the active-provider handling.
webllm.ts: provider using `CreateMLCEngine` from @mlc-ai/web-llm with AI.webllmModelId; report progress via the init progress callback; if `navigator.gpu` is missing or load fails, throw a typed error that the UI maps to FALLBACK status. Use temperature 0.3.
ollama.ts: provider calling `${AI.ollamaUrl}/api/chat` with stream false; clear error message if unreachable ("Ollama not reachable. Start it with OLLAMA_ORIGINS set, or use the template narrator."). P1 — keep small.
template.ts: the always-available deterministic narrator. Export narrateAnalyst(facts, lang), narrateRisk(flags, lang), narrateCfo(facts, flags, lang): CfoMemo, and narrateAnswer(toolResult, lang). Each uses sentence templates in English and Hinglish (Roman letters only, short sentences, technical terms in English, 0–1 emoji). Example Hinglish: "Cash lagbhag 41 din chalega, bhau. Tuesday ki sales average se 31% kam hain." These are the safe fallback for every AI call.
prompts.ts: export NARRATOR_SYSTEM(lang) with this exact intent: "You are Munim, a calm, careful accountant's assistant for a small shop owner in India. You will be given FACTS as JSON. Use ONLY numbers that appear in FACTS — never calculate, estimate, or invent any new number. Never give tax, legal, or investment advice; say 'confirm with your CA' if asked. Write at most 2 short sentences. Explain what the numbers mean for the business and never blame the owner." For hinglish add: "Write in Hinglish — Hindi words in Roman letters mixed with simple English, keep terms like cash, sales, expenses, runway in English; no Devanagari; 0–1 emoji." For english add: "Write in plain simple English." Also export CFO_SYSTEM(lang) requiring a JSON object { "headline": string, "actions": [string, string, string] } with the same number rule, and ROUTER_SYSTEM listing the six tool names with their argument shapes and demanding JSON { "tool": string, "args": object } only. Export user-prompt builders that stringify the minimal FACTS subset each agent needs (keep prompts short — this is a 1.5B model).
guard.ts: validateNarration(text, facts): extract every number token from the AI text and confirm each appears (after normalising ₹, commas, %, 'days') in a flattened set of allowed numbers built from the FACTS passed in; if any number is not allowed, return false. Every AI narration must pass this guard or be replaced by the template narration. Also parse+validate JSON for CFO and router outputs (strip code fences defensively).
router.ts: routeQuestion(question, provider, facts, lang): if provider is ready, ask the LLM with ROUTER_SYSTEM (json: true, max 80 tokens), validate that tool is one of ToolName and args are well-formed; on any failure fall back to keywordRouter(question) which maps words like "best/worst day", "tuesday/monday…", "afford/buy", "runway/how long", "spend/expense", "sales/revenue" to a tool. Never fail silently into nothing — default to runwayNow.

=== 9. lib/agents/ ===
Each agent is an async function (ctx) -> AgentState where ctx = { transactions, report, facts, provider, lang }. Each agent produces a deterministic `factLine` (shown with a "calculated by code" tag) and optionally `narration` (tag "narrated by AI" if the model produced it and passed the guard, otherwise "template").
- cleaner.ts: no LLM. factLine from CleanReport, e.g. "Read 118 rows, kept 112, fixed 6 dates and 9 amounts."
- analyst.ts: facts = trend vs previous 30 days, best/worst weekday, cash share, top expense category; LLM narration (max AI.maxTokensNarration) validated by guard else template.
- tax.ts: no LLM for numbers; factLine = "GST payable est. ₹X · income tax est. ₹Y"; always attaches TAX_DISCLAIMER.
- risk.ts: uses buildFlags; LLM narrates the single most severe flag in one sentence, guard + template fallback.
- cfo.ts: gives all agent facts to the CFO prompt, expects JSON { headline, actions[3] }, validates with guard.ts, falls back to narrateCfo template.
orchestrator.ts: runAnalysis(input, provider, lang, onUpdate: (agents: AgentState[]) => void): runs agents sequentially, setting each to "working" then "done" (or "fallback" when the template was used after an AI failure), calling onUpdate on every change, enforcing AI.timeoutMs per LLM call via Promise.race, and never throwing — any agent error becomes a "fallback" state with template output. Insert a minimum visible 350ms between agents so the Agent Room is readable in a demo even when the template narrator is instant.
````
